# Study02_ToDoList

바닐라 자바스크립트로 만드는 개인용 할 일 관리 앱. **프레임워크 없이** 상태 관리, DOM 렌더링, 데이터 영속화의 기본기를 익히는 학습 프로젝트입니다.

> **현재 상태: 설계 단계** — PRD 작성이 완료되었고 구현은 시작 전입니다.

---

## 무엇을 만드나

하루 10~20개의 할 일을 관리하는 단일 화면 웹앱입니다.

- 할 일 추가 / 수정 / 삭제
- 완료 체크
- 카테고리 분류 — 업무 / 개인 / 공부
- 카테고리별 필터링
- 진행률 표시
- 완료 항목 일괄 정리
- 새로고침 후에도 데이터 유지 (`localStorage`)

```
┌────────────────────────────────────────┐
│  할 일 관리                             │
├────────────────────────────────────────┤
│  [할 일 입력...        ] [업무▾] [추가] │
├────────────────────────────────────────┤
│  ████████░░░░░░░░░░  4 / 15 완료 (27%) │
├────────────────────────────────────────┤
│  [전체] [업무] [개인] [공부]            │
├────────────────────────────────────────┤
│  ☐  PRD 리뷰하기          업무  ✎  🗑   │
│  ☑  장보기                개인  ✎  🗑   │
│  ☐  알고리즘 2문제        공부  ✎  🗑   │
├────────────────────────────────────────┤
│                      [완료 항목 비우기] │
└────────────────────────────────────────┘
```

## 학습 목표

이 프로젝트는 기능 구현 자체보다 **아래 다섯 가지를 설명할 수 있게 되는 것**을 성공 기준으로 삼습니다.

1. 왜 DOM이 아니라 상태가 진실의 원천(source of truth)인가
2. 전체 재렌더가 왜 이 규모에서 괜찮은가, 그리고 언제부터 괜찮지 않게 되는가
3. 이벤트 위임이 전체 재렌더 방식과 어떤 관계인가
4. 무엇을 저장하고 무엇을 저장하지 않는가 — 영속 데이터와 UI 상태의 구분
5. 파생값(진행률)을 저장하지 않는 이유

## 설계 요약

### 렌더링 방식

```
state 변경 → localStorage 저장 → 구독자 알림 → render() → DOM 전체 갱신
```

항목이 10~20개 규모라 전체 재렌더 비용이 사실상 0입니다. 프레임워크가 가상 DOM으로 푸는 문제가 이 규모에서는 발생하지 않습니다. 동시에 "상태가 진실, DOM은 그 결과물"이라는 멘탈 모델은 이후 React나 Vue로 넘어갈 때 그대로 이어집니다.

### 모듈 구조

```
main.js  ──사용──▶  store.js  ──사용──▶  storage.js  ──▶ localStorage
   │                   │
   └──사용──▶  render.js  ◀──상태를 인자로 받음──┘
```

의존이 한 방향으로만 흐르고 순환이 없습니다. `render.js`는 아무것도 import하지 않는 순수 함수의 모음이라, 가짜 상태를 넣어 독립적으로 테스트할 수 있습니다.

| 파일 | 책임 |
|---|---|
| `index.html` | 마크업 뼈대 |
| `style.css` | 스타일 |
| `js/storage.js` | `localStorage` 입출력 — 저장소를 아는 유일한 파일 |
| `js/store.js` | 상태와 변경 함수 |
| `js/render.js` | 상태 → DOM |
| `js/main.js` | 이벤트 연결 및 조립 |
| `test.html` | 순수 함수 자동 테스트 |

## 기술 제약

- **프레임워크·라이브러리 사용 금지** — 순수 자바스크립트만
- **빌드 도구·npm 의존성 0개**
- ES 모듈(`import` / `export`)로 파일 분리
- 대상 브라우저: 최신 Chrome / Edge / Firefox

## 실행 방법

> 구현 완료 후 사용할 수 있습니다.

ES 모듈을 사용하므로 **로컬 정적 서버가 필요합니다.**

```bash
npx serve
```

또는 VS Code의 **Live Server** 확장을 사용하세요.

`index.html`을 더블클릭해 `file://`로 여는 방식은 **지원하지 않습니다.** ES 모듈이 CORS 정책으로 차단되고, 모든 로컬 파일이 동일한 `localStorage` 공간을 공유해 다른 실습 파일과 충돌할 수 있기 때문입니다.
