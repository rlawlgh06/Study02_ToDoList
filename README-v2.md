# Study02_ToDoList

브라우저에서 바로 실행되는 개인용 할 일 관리 앱이다. 하루 10~20개 수준의 할 일을 적어 두고, 카테고리로 나눠 보면서 완료 여부와 진행률을 확인한다.

서버도 계정도 빌드 도구도 없다. HTML 파일 하나를 브라우저로 열면 실행되고, 데이터는 브라우저의 localStorage에 남는다.

## 현재 상태

**v1 구현 완료.** PRD 10장의 완료 기준 11개를 모두 통과했다.

- [index.html](index.html) — 앱 전체 (HTML + CSS + 자바스크립트)
- [PRD.md](PRD.md) — 요구사항, 데이터 모델, 완료 기준, 설계 결정의 근거
- [PROMPTS.md](PROMPTS.md) — PRD를 클로드 코드에서 실행할 5단계 프롬프트로 나눈 것

## 기능

- 할 일 추가, 수정, 삭제
- 완료 체크
- 카테고리 분류 (업무, 개인, 공부)
- 카테고리 필터
- 진행률 보기 (현재 선택된 필터 기준)
- 새로고침해도 유지되는 저장

```
┌─────────────────────────────────────────────┐
│  할 일 관리                                  │
│  ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░  7 / 12 (58%)         │
├─────────────────────────────────────────────┤
│  [ 할 일을 입력하세요    ] [업무▾] [추가]      │
├─────────────────────────────────────────────┤
│  [ 전체 ] [ 업무 ] [ 개인 ] [ 공부 ]          │
├─────────────────────────────────────────────┤
│  ☐  PRD 검토 마무리       [업무] [수정][삭제]  │
│  ☑  ~~장보기~~            [개인] [수정][삭제]  │
│  ☐  자바스크립트 3장 읽기  [공부] [수정][삭제]  │
└─────────────────────────────────────────────┘
```

자세한 요구사항과 완료 기준은 [PRD.md](PRD.md)에 있다.

## 기술 스택

- HTML, CSS, 순수 자바스크립트
- 라이브러리와 프레임워크 없음
- 파일 구성: `index.html` 하나 (CSS와 자바스크립트를 같은 파일 안에 둔다)
- ES 모듈은 쓰지 않는다. `file://`로 열면 CORS 정책에 막히기 때문이다

## 실행 방법

`index.html`을 브라우저로 열기만 하면 된다. 설치할 것도, 띄울 서버도 없다.

## 학습 목표

이 프로젝트는 기능 구현보다 **아래를 설명할 수 있게 되는 것**을 성공 기준으로 삼는다.

1. 왜 DOM이 아니라 상태가 진실의 원천인가
2. 전체 재렌더가 왜 이 규모에서 괜찮은가, 언제부터 괜찮지 않게 되는가
3. 이벤트 위임이 전체 재렌더와 어떤 관계인가
4. 무엇을 저장하고 무엇을 저장하지 않는가
5. 파생값(진행률)을 저장하지 않는 이유

## 범위 밖

마감일, 우선순위, 정렬, 검색, 반복 할 일, 하위 항목, 로그인, 서버 동기화, 알림, 통계, 되돌리기, 다크 모드.

없어서 빠진 것이 아니라 범위를 지키려고 뺀 것이다. 각 항목의 사유는 PRD 2장에 적어 두었다.

## 배경

『바이브 코딩』 4장 실습으로 만드는 앱이다. 클로드에게 PRD를 쓰게 하고, 그 PRD를 바탕으로 구현까지 진행하는 과정을 담는다.
